# Purge - массовое удаление сообщений (`!purge`)

## Назначение
Массовое удаление сообщений в канале модератором, с несколькими режимами отбора (по автору, по содержимому, по типу вложения). **Запасной контур**: та же функциональность уже есть на сервере у стороннего бота **Dyno** - доступна и как `/purge`, и как `?purge` (префикс `?`), но Dyno периодически перестаёт работать - `!purge` у Коннора существует именно как резерв на этот случай, не как основной инструмент.

## Команда
`!purge` - **только префиксная**, только префикс `!` (без slash-варианта `/purge`, аналогично [`!kiss`](../base.md), исключение из общего правила "каждая команда доступна и как `/`, и как `!`"). Важно не путать с `/purge`/`?purge` - обе принадлежат **Dyno**, другому боту на сервере; Коннор реагирует строго на `!`, чтобы не конфликтовать с Dyno.

## Синтаксис (варианты)
| Вызов | Действие |
|---|---|
| `!purge <count>` | Удалить последние `<count>` сообщений в канале (любые) |
| `!purge user <@упоминание\|id> <count>` | Удалить `<count>` **подходящих** сообщений конкретного пользователя |
| `!purge match <текст> <count>` | Удалить `<count>` подходящих сообщений, содержащих `<текст>` |
| `!purge not <текст> <count>` | Удалить `<count>` подходящих сообщений, НЕ содержащих `<текст>` |
| `!purge links <count>` | Удалить `<count>` подходящих сообщений, содержащих ссылки |
| `!purge images <count>` | Удалить `<count>` подходящих сообщений, содержащих изображения |
| `!purge text <count>` | Удалить `<count>` подходящих сообщений, содержащих только текст (без вложений/ссылок) |

Для всех вариантов с фильтром (`user`/`match`/`not`/`links`/`images`/`text`) семантика `<count>` - **количество подходящих под критерий сообщений**, не размер окна сканирования: бот сканирует историю канала вглубь (от точки вызова команды), пока не наберёт `<count>` подходящих сообщений (либо не упрётся в мягкий лимит, либо не кончится история). Для базового `!purge <count>` (без фильтра) - просто последние `<count>` сообщений подряд.

**Семантика фильтров:**
- `match`/`not` - сравнение подстрокой, без учёта регистра (та же логика, что и у списка слов в [moderationChat.md](moderationChat.md)) - `<текст>` ищется где угодно внутри сообщения, границы слова не проверяются.
- `links` - сообщение содержит любой `http(s)://` URL в тексте, простой паттерн-мэтч; не привязано к определению "медиа" из moderationChat.md - под фильтр попадает любая ссылка, не только медийная.
- `images` - сообщение содержит вложение (attachment) с image content-type. Это **уже**, чем "медиа" в moderationChat.md (там же считаются видео/аудио и GIF-ссылки из текста) - `images` фильтрует только картинки-вложения; ссылка на картинку в тексте под этот режим не попадает (это уже `links`).

Работает в любых текстовых чатах сервера - обычные каналы, треды/ветки, и текстовые чаты приватных голосовых комнат ("Открыть чат"/Voice Text Chat, см. [Voices.md](Voices.md)); единственное исключение - модераторская категория "роддом" (см. "Ограничение по каналам" ниже). Сообщения от **других ботов** (в т.ч. Dyno) в выборку под удаление не попадают - бот их пропускает при сканировании, как и в [moderationChat.md](moderationChat.md).

## Права на вызов
Проверяется **эффективное право Discord "Управлять сообщениями"** (Manage Messages) у вызвавшего в этом канале (`channel.permissions_for(member)`/аналог) - не привязано к конкретной роли по ID, аналогично проверке доступа в [check.md](check.md). Если права нет - команда **тихо игнорируется**, без ответа об ошибке (та же модель, что и у command permissions для `!`-команд, см. [rules.md](../rules.md) "Роли и права").

## Ограничение по каналам
Команда **не работает внутри модераторской категории "роддом"** - то же исключение по ID категории (`channel.category_id`, с резолвингом через родительский канал для тредов), что и в [moderationChat.md](moderationChat.md). При вызове внутри категории - тоже **тихо игнорируется**, без ответа.

## Мягкий лимит на количество
`<count>` ограничен потолком **300** сообщений за вызов (конфигурируемая константа модуля, см. [environment.md](../environment.md) "Конфигурация"). Лимит **мягкий**: если запрошено больше потолка (например, `!purge 1000`), команда не отклоняется и не ошибается - просто удаляется максимум 300, который бот может обработать, без явной ошибки о превышении.

**Замечание к реализации**: Discord API отдаёт bulk-delete пачками максимум по 100 сообщений за вызов - для мягкого лимита в 300 потребуется до 3 последовательных вызовов bulk-delete подряд (в пределах 14-дневного окна, см. ниже).

## Граница 14 дней (bulk-delete)
Discord позволяет массово удалять (bulk-delete) только сообщения младше 14 дней. При сканировании истории для фильтров (`match`/`not`/`user`/`links`/`images`/`text`) - как только сканирование упирается в сообщение старше 14 дней, **сканирование останавливается на этой границе**, даже если `<count>` ещё не набрано - сообщения старше границы не удаляются вообще (ни поштучно, ни как-то иначе).

## Обработка ошибок (точные тексты)
| Ситуация | Ответ бота |
|---|---|
| `<count>` не число / отсутствует / ноль / отрицательное | `Количество указано не верно` |
| Прочая ошибка разбора команды (неизвестный режим фильтра, некорректный синтаксис вызова) | `Команда указана не верно.` |

Отдельно от этого - нехватка права "Управлять сообщениями" или вызов внутри категории "роддом" (см. выше) остаются **тихим игнором**, без ответа вообще; таблица выше - только про ошибки разбора самой команды, когда право на вызов есть и канал разрешён.

## Ответ бота
- В канале, где вызвана команда, - реакция **:pudge:** (эмодзи-реакция на сообщение с вызовом команды, не текстовый ответ).
- В `#бот-команды` - embed (пример: `!purge text 1`, вызванная в `#флудиславль`):
  - **author** эмбеда = глобальный никнейм Discord + аватар вызвавшего модератора (например, `.destroyko` - то, что видно в профиле, не серверный nickname);
  - **тело** (дословно, пример): `<упоминание автора без квота> использовал :pudge: text 1 в канале #флудиславль`. Разбор:
    - `<упоминание автора без квота>` - тот же модератор, но **не настоящий Discord-пинг** (не уведомляет адресата), просто текстовое отображение его серверного nickname (в примере - `enteii`);
    - `:pudge:` - тот же кастомный эмодзи, что и в реакции на канале вызова (см. пункт выше);
    - `<режим и аргументы>` - сабкоманда и переданные параметры как они были введены (в примере: `text 1`);
    - `<канал>` - канал, где вызвана команда.

  Embed показывает только исходные аргументы вызова - итоговое число реально удалённых сообщений отдельно **не указывается**.

## Хранимые данные
Не требуется - операция разовая, без персистентного состояния.
