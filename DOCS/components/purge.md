# Purge — массовое удаление сообщений (`!purge`)

> Не путать с исключённой из скоупа функцией "очистка чатов" (см. [base.md](../base.md) "Исключено из скоупа") — та относится к ДРУГОМУ боту сервера. `!purge`, описанный здесь, — подтверждённая функция самого Коннора.

## Назначение
Массовое удаление сообщений в канале модератором, с несколькими режимами отбора (по автору, по содержимому, по типу вложения). **Запасной контур**: на сервере уже стоит сторонний бот **Dyno** с похожей функцией (`?purge`, префикс `?`), но он периодически перестаёт работать — `!purge` у Коннора существует именно как резерв на этот случай, не как основной инструмент.

## Команда
`!purge` — **только префиксная**, только префикс `!` (без slash-варианта `/purge`, аналогично [`!kiss`](../base.md), исключение из общего правила "каждая команда доступна и как `/`, и как `!`"). Важно не путать с `?purge` — это команда **Dyno**, другого бота на сервере; Коннор реагирует строго на `!`, чтобы не конфликтовать с Dyno.

## Синтаксис (варианты)
| Вызов | Действие |
|---|---|
| `!purge <count>` | Удалить последние `<count>` сообщений в канале (любые) |
| `!purge user <@упоминание\|id> <count>` | Удалить `<count>` **подходящих** сообщений конкретного пользователя |
| `!purge match <текст> <count>` | Удалить `<count>` подходящих сообщений, содержащих `<текст>` |
| `!purge not <текст> <count>` | Удалить `<count>` подходящих сообщений, НЕ содержащих `<текст>` |
| `!purge links <count>` | Удалить `<count>` подходящих сообщений, содержащих ссылки |
| `!purge images <count>` | Удалить `<count>` подходящих сообщений, содержащих изображения |
| `!purge text <count>` | Удалить `<count>` подходящих сообщений, содержащих только текст (без вложений/ссылок) |

Для всех вариантов с фильтром (`user`/`match`/`not`/`links`/`images`/`text`) семантика `<count>` — **количество подходящих под критерий сообщений**, а не размер окна сканирования: бот сканирует историю канала вглубь (от точки вызова команды), пока не наберёт `<count>` подходящих сообщений (либо не упрётся в мягкий лимит, либо не кончится история). Для базового `!purge <count>` (без фильтра) — просто последние `<count>` сообщений подряд.

Работает и внутри тредов (веток), не только в обычных текстовых каналах. Сообщения от **других ботов** (в т.ч. Dyno) в выборку под удаление не попадают — бот их пропускает при сканировании, как и в [moderationWords.md](moderationWords.md)/[moderationMedia.md](moderationMedia.md).

## Права на вызов
Проверяется **эффективное право Discord "Управлять сообщениями"** (Manage Messages) у вызвавшего в этом канале (`channel.permissions_for(member)`/аналог) — не привязано к конкретной роли по ID, аналогично проверке доступа в [check.md](check.md). Если права нет — команда **тихо игнорируется**, без ответа об ошибке (та же модель, что и у command permissions для `!`-команд, см. [base.md](../base.md) "Роли и права").

## Ограничение по каналам
Команда **не работает внутри модераторской категории "роддом"** — то же исключение по ID категории (`channel.category_id`, с резолвингом через родительский канал для тредов), что и в [moderationWords.md](moderationWords.md)/[moderationMedia.md](moderationMedia.md). При вызове внутри категории — тоже **тихо игнорируется**, без ответа.

## Мягкий лимит на количество
`<count>` ограничен потолком **300** сообщений за вызов (конфигурируемая константа модуля, см. [base.md](../base.md) "Конфигурация"). Лимит **мягкий**: если запрошено больше потолка (например, `!purge 1000`), команда не отклоняется и не ошибается — просто удаляется максимум 300, который бот может обработать, без явной ошибки о превышении.

## Граница 14 дней (bulk-delete)
Discord позволяет массово удалять (bulk-delete) только сообщения младше 14 дней. При сканировании истории для фильтров (`match`/`not`/`user`/`links`/`images`/`text`) — как только сканирование упирается в сообщение старше 14 дней, **сканирование останавливается на этой границе**, даже если `<count>` ещё не набрано — сообщения старше границы не удаляются вообще (ни поштучно, ни как-то иначе).

## Ответ бота
- В канале, где вызвана команда, — реакция **:pudge:** (эмодзи-реакция на сообщение с вызовом команды, не текстовый ответ).
- В `#бот-команды` — embed (подтверждено, пример: `!purge text 1`, вызванная в `#флудиславль`):
  - **author** эмбеда = глобальный никнейм Discord + аватар вызвавшего модератора (например, `.destroyko` — то, что видно в профиле, а не серверный nickname);
  - **тело** (дословно, пример): `<упоминание автора без квота> использовал :pudge: text 1 в канале #флудиславль`. Разбор:
    - `<упоминание автора без квота>` — тот же модератор, но **не настоящий Discord-пинг** (не уведомляет адресата), просто текстовое отображение его серверного nickname (в примере — `enteii`);
    - `:pudge:` — тот же кастомный эмодзи, что и в реакции на канале вызова (см. пункт выше);
    - `<режим и аргументы>` — сабкоманда и переданные параметры как они были введены (в примере: `text 1`);
    - `<канал>` — канал, где вызвана команда.

  Embed показывает только исходные аргументы вызова — итоговое число реально удалённых сообщений отдельно **не указывается**.

## Хранимые данные
Не требуется — операция разовая, без персистентного состояния.

## Открытые вопросы
Нет.

**Замечание к реализации**: Discord API отдаёт bulk-delete пачками максимум по 100 сообщений за вызов — для мягкого лимита в 300 потребуется до 3 последовательных вызовов bulk-delete подряд (в пределах 14-дневного окна, см. выше).
