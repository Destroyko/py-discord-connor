# Mute

## Назначение
Выдача временного запрета на общение (текст + голос) пользователю по команде модератора.

## Команды
| Команда | Синтаксис | Права |
|---|---|---|
| `/mute` | `target:<упоминание или id> time:<60s-28d> reason:[опционально]` | Модератор; именованные параметры slash-команды |
| `!mute` | `<упоминание или id> <time 60s-28d> [reason]` | Модератор; позиционные аргументы через один пробел |
| `/unmute` | `target:<упоминание или id>` | Модератор |
| `!unmute` | `<упоминание или id>` | Модератор |

Примеры:
```
!mute 569878391927341056 24h п12
!mute @enteii 24h п12
/mute target:569878391927341056 time:24h reason:п12
/mute target:@enteii time:24h reason:п12
```

`target` принимает либо raw id пользователя, либо упоминание через `@` (mention). Reply на сообщение пользователя как способ указать цель **не поддерживается**.

## Механизм наказания (двойной)
1. **Discord timeout** (`communication_disabled_until`, нативный API Discord) - реальный блокирующий механизм: не даёт писать в текст, реагировать, заходить в войс. Если пользователь в момент наложения находится в войсе - Discord **немедленно отключает** его от голосового канала сам, без участия бота; повторно зайти в войс на время таймаута он не может. Ограничение самого Discord API: **максимум 28 дней**, отсюда верхняя граница `<time>`.
2. **Роль "Молчун"** - выдаётся параллельно, **чисто визуально** (не несёт собственных permission overwrites, ничего не блокирует сама по себе). Нужна, чтобы другие участники видели по бейджу роли, что на пользователе висит наказание.

## Уведомление в ЛС (DM)
При выдаче мута и при ручном снятии через `!unmute`/`/unmute` бот отправляет пользователю личное сообщение.

При первой выдаче - embed с зелёной полосой слева:
```
Вы получили мут на сервере "<название сервера>" продолжительностью <time>

Причина
<причина, либо "Причина не указана">

Правила сервера   ← ссылка

Для обжалования вы можете обратиться к старшим модераторам или супермодераторам,
перед обращением рекомендуем ознакомиться с разделом правил сервера
```
Ссылка "Правила сервера" - значение из конфига модуля mute (см. [environment.md](../environment.md) "Конфигурация"), не хардкод в тексте шаблона и не `.env`. При смене адреса правил достаточно поправить конфиг, без правки кода/текста сообщения.

При **обновлении** уже активного мута (повторный `!mute`/`/mute` на уже замьюченном, см. "Логика работы" ниже) - тот же шаблон, но с другой первой строкой и другой полосой (жёлтая):
```
Вам обновили время мута на сервере "<название сервера>" продолжительностью <new_time>

Причина
<новая причина, либо "Причина не указана">

Правила сервера   ← ссылка

Для обжалования вы можете обратиться к старшим модераторам или супермодераторам,
перед обращением рекомендуем ознакомиться с разделом правил сервера
```

При ручном снятии - обычное текстовое сообщение (не embed):
```
Ограничения на сервере "<название сервера>" сняты
```

DM о снятии отправляется **только** при ручном `!unmute`/`/unmute`. При естественном истечении таймаута никаких оповещений не отправляется - ни DM пользователю, ни сообщение в канал логов.

**Отказ пользователя от DM**: пользователь может закрыть приём личных сообщений от участников сервера - тогда отправка DM-уведомления при муте закономерно упадёт с ошибкой на стороне Discord API. Мут/анмут при этом всё равно выполняется (DM - не блокирующий шаг). Ошибка отправки логируется ботом для себя (не пользователю и не в публичный канал) - специального уведомления модератору об этом не предусмотрено.

## Логика работы `!mute`
1. Валидация аргументов (для `!mute` - позиционные, разделены одним пробелом: `<target> <time> [reason]`; для `/mute` - именованные параметры `target`/`time`/`reason`):
   - `target` - id или `@упоминание`; невалиден/не резолвится → `"Укажите пользователя или id"`; корректный id, но пользователь **не на сервере** (Discord timeout применим только к текущим участникам, в отличие от бана) → `"Укажите пользователя или id. Также возможно пользователь уже отсутствует на сервере"` (тот же текст, что и у `/ban` в аналогичном случае, см. [banKick.md](banKick.md))
   - `time` вне диапазона 60s–28d или в неверном формате → `"Время указано некорректно"`. Формат - одно число + один суффикс (`s`/`m`/`h`/`d`); составной формат (`1h30m`) не поддерживается. Дробное число (например, `1.5h`) - та же ошибка `"Время указано некорректно"`, отдельного текста для этого случая нет.
   - Проверка иерархии: цель - роль выше или равная роли инициатора, ИЛИ цель - бот → отказ: `"Вы не можете мутить старших или эквивалентных по роли или ботов"` (см. [rules.md](../rules.md) "Роли и права" - общая проверка иерархии для всех наказаний)
   - Проверка на самомодерацию: цель - сам инициатор команды → отказ: `"Что ты делаешь?"` (отдельная проверка от иерархии, см. [rules.md](../rules.md) "Роли и права")
2. Если пользователь **уже замьючен** - мут не отклоняется, а **обновляется**: новые `<time>`/`<reason>` заменяют старые (таймаут пересчитывается заново от текущего момента на новую `<time>`, не суммируется с оставшимся временем старого мута). **Обновление доступно только с учётом резервации за автором** - см. "Резервация после наложения мута" ниже; если вызывающий не имеет права обновить прямо сейчас, вместо обновления - отказ `Пользователь уже в муте`.
   - при разрешённом обновлении, в `#бот-команды` - embed с **жёлтой** полосой слева: author = ник + аватар модератора, вызвавшего команду; текст `@упоминание перемьючен с <old_time> на <new_time>`; блок **Причина**: новая причина (заменяет старую).
   - пользователю уходит DM об обновлении (см. [Уведомление в ЛС](#уведомление-в-лс-dm), вариант "при обновлении").
3. При успехе (первая выдача, пользователь ещё не был замьючен):
   - выставляется Discord timeout на `<time>`;
   - выдаётся роль "Молчун";
   - пользователю отправляется DM-уведомление (см. [Уведомление в ЛС](#уведомление-в-лс-dm));
   - в канал `#бот-команды` (см. [base.md](../base.md)) отправляется embed-ответ с **зелёной** полосой слева:
     - author эмбеда = ник + аватар модератора, вызвавшего команду;
     - текст: `@упоминание замьючен на <time>`;
     - блок **Причина**: указанная причина, либо `"Причина не указана"`, если не передана.

## Резервация после наложения мута (защита от гонки между модераторами)
Разрешает конфликт между общим правилом "гонки одинаковых команд" (см. [rules.md](../rules.md) "Роли и права") и update-поведением `/mute` (п.2 выше): без этого механизма два модератора, почти одновременно вызвавшие `/mute` на одну цель, либо гонялись бы за тем, чей вызов "победит" в перезаписи причины/времени, либо второй вызов терялся бы без объяснения.

- Как только `/mute` успешно применяет наказание на **не замьюченную** цель (первое наложение текущего цикла мута) - вызвавший модератор становится **владельцем резервации** на этой цели на **60 секунд**, отсчитываемых от момента этого первого наложения.
- В течение этого окна:
  - **тот же модератор** может вызывать `/mute` на эту же цель повторно сколько угодно раз - каждый раз это штатное обновление ("премут", см. п.2 выше: новые `<time>`/`<reason>` заменяют старые, жёлтый embed + DM);
  - **любой другой** модератор, вызвавший `/mute` на ту же цель в этом же окне, получает отказ **без** наложения/обновления мута: `Пользователь уже в муте`.
- Окно **фиксированное**, не продлевается последующими "премутами" того же модератора - отсчёт всегда от самого первого наложения текущего цикла мута.
- По истечении 60 секунд резервация снимается - обновить мут может **любой** модератор, без ограничения по автору (обычное поведение обновления из п.2 выше).
- Резервация привязана к конкретному активному циклу мута: если мут снят (`/unmute` или истечение таймаута) и наложен заново - 60-секундное окно и владелец резервации отсчитываются заново от нового наложения.

## Логика `!unmute`
1. Если цель не в муте - отказ: обычным текстовым сообщением (не embed), реплаем на команду, - `Пользователь не в муте`.
2. Пытается снять и Discord timeout, и роль "Молчун" одновременно.
3. Если снятие роли не удалось (например, недостаточно прав/гонка состояний) - роль не считается критичной: она будет убрана позже реконсиляцией (см. ниже), явной ошибки пользователю в этом случае не выводится (тихий фолбэк).
4. Пользователю отправляется DM-уведомление о снятии ограничений (см. [Уведомление в ЛС](#уведомление-в-лс-dm)).

## Реконсиляция роли "Молчун" (self-heal)
- **Ключевая механика**: роль - это отдельное состояние от реального Discord-таймаута, поэтому может рассинхронизироваться в обе стороны.

### Направление 1: роль есть, таймаута уже нет
- Причины: таймаут истёк сам по себе, снят вручную через Discord UI, или `!unmute` не смог снять роль.
- При получении любого сообщения от пользователя, а также при попытке зайти в войс, бот проверяет: если у автора есть роль "Молчун", но активного timeout уже нет → роль снимается.
- Это единственные точки, где это направление расхождения исправляется - до одного из этих событий роль может провисеть сколько угодно после истечения реального мута (тишина, никаких автоуведомлений об окончании мута).

### Направление 2: таймаут есть, роли уже нет (после выхода/повторного входа на сервер)
- **Важно**: при выходе с сервера Discord снимает с пользователя ВСЕ роли, включая "Молчун". Но нативный Discord timeout (`communication_disabled_until`) - серверная модерационная запись, привязанная к паре пользователь-сервер (не к текущему членству), и **переживает выход/повторный вход** (это штатное поведение Discord, специально сделанное так, чтобы выходом с сервера нельзя было обойти таймаут).
- Следствие: если замьюченный пользователь выходит и почти сразу заходит обратно, он окажется реально замьючен (Discord timeout действует), но роль "Молчун" - визуальный индикатор - будет отсутствовать, пока это не исправят.
- Реконсиляция в эту сторону: при повторном входе пользователя на сервер (`on_member_join`/аналог) бот должен проверить, не висит ли на нём всё ещё активный timeout, и если да - заново выдать роль "Молчун" для восстановления визуальной индикации.

## Обработка ошибок (точные тексты)
| Ситуация | Ответ бота |
|---|---|
| Некорректный/отсутствующий `user_id` | `Укажите пользователя или id` |
| Корректный `user_id`, но пользователь не на сервере | `Укажите пользователя или id. Также возможно пользователь уже отсутствует на сервере` |
| `time` вне 60s–28d или неверный формат | `Время указано некорректно` |
| Цель - роль выше/равна инициатору, или цель - бот | `Вы не можете мутить старших или эквивалентных по роли или ботов` |
| Цель - сам инициатор команды | `Что ты делаешь?` |
| `/unmute` на пользователе, который не в муте | `Пользователь не в муте` (обычный текст, не embed, реплаем на команду) |
| `/mute` на уже замьюченной цели другим модератором в пределах 60-секундного окна резервации (см. "Резервация после наложения мута" выше) | `Пользователь уже в муте` |

## Хранимые данные
- Явного отдельного хранилища не требуется для самого мута - источник истины: Discord timeout (`communication_disabled_until`) + факт наличия роли "Молчун". Причина мута нигде не хранится персистентно за пределами embed-сообщения в чате - ни в `#антиработяги`, ни в `#аудит` мут/анмут не дублируется (см. [base.md](../base.md) "Каналы, завязанные на бота").
- **Резервация после наложения мута**: пара (id модератора-владельца резервации, timestamp первого наложения текущего цикла) на замьюченного пользователя - должна храниться хотя бы на время окна в 60 секунд (в памяти или в БД; переживать рестарт бота не обязательно - по истечении окна резервация в любом случае теряет смысл).
