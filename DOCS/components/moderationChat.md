# ModerationChat - пассивный мониторинг сообщений (слова и медиа)

## Назначение
Пассивный мониторинг всех текстовых сообщений сервера по двум независимым критериям - подозрительные слова и медиавложения - с пересылкой в отдельные модераторские чаты для ручной оценки. Без автоматических действий над самим сообщением: слово или медиа не всегда являются нарушением сами по себе, решение остаётся за модератором.

## Общие правила фильтрации
Общие для обоих критериев (слова / медиа) - применяются независимо, каждый критерий проверяется сам по себе:
1. Проверяются только **новые** сообщения от **пользователей**. Сообщения от **любых** ботов, включая себя, пропускаются целиком, не проверяются вообще. Редактирование сообщений (`message edit`) не отслеживается ни для одного из критериев - добавленное постфактум вложение или слово не ловится.
   - **Замечание к реализации**: исключение обязано покрывать и сообщения, отправленные через **вебхук** (например, сторонние логеры/интеграции наподобие MEE6) - в некоторых Discord-библиотеках у такого сообщения `author` не гарантированно помечен как `bot` (это отдельная, "чужая" для аккаунтов сущность), поэтому проверку нельзя ограничивать только флагом `author.bot` - нужно отдельно проверять `message.webhook_id is not None` (или аналог в используемой библиотеке) и пропускать такие сообщения тоже.
2. Проверка применяется ко всем каналам сервера, **кроме** каналов внутри модераторской категории "роддом" (например, `#бот-команды`, `#антиработяги` и т.п. - категория без тредов/форумов внутри). Реализуется через ID самой категории (`.env`), без перечисления отдельных каналов - сравнивается `channel.category_id` с этим ID, так исключение автоматически покрывает любой канал, который позже добавят в категорию или уберут из неё.
   - **Замечание к реализации**: сервер активно использует треды/ветки (см. [base.md](../base.md) - масштаб "80+ каналов/веток/форумов"). У объекта треда в большинстве Discord-библиотек нет прямого `category_id` - у него есть родительский канал (`thread.parent`), и уже у родителя есть `category_id`. Проверка исключения обязана резолвить тред → родительский канал → `category_id` родителя: чтение `category_id` напрямую с объекта треда упадёт или даст неверный результат.
   - **Текстовые чаты приватных голосовых комнат** ("Открыть чат"/Voice Text Chat, см. [Voices.md](Voices.md)) - тоже подпадают под проверку, как обычный текстовый канал: комнаты лежат в отдельной, не "роддом", категории (см. [base.md](../base.md) "Каналы, завязанные на бота"), под общее исключение не попадают. У голосового канала `category_id` есть напрямую - дополнительная логика резолвинга, как для тредов выше, не нужна.
3. **Пересечение критериев**: если сообщение одновременно содержит подозрительное слово И медиавложение - оно попадает **в оба** чек-листа независимо, каждый механизм срабатывает по своему критерию сам по себе.

## Слова → `#чек-лист`
1. Проверка идёт по внутреннему списку подозрительных слов/фраз - простой plain-список без паттернов/регулярок (источник списка - конфиг-файл модуля, см. [environment.md](../environment.md) - "Конфигурация"). Список меняется только ручной правкой конфига (с рестартом бота) - отдельной команды для редактирования на лету нет.
2. Сравнение - **подстрокой, без учёта регистра**, по всему тексту сообщения целиком (слово не обязано быть отдельным сообщением само по себе - сообщение может быть длинным, слово-триггер просто где-то внутри). Границы слова не проверяются: срабатывание засчитывается, даже если триггер - часть более длинного слова - иначе фильтр легко обойти, вставив запрещённое слово внутрь другого.
3. При срабатывании - пересылает в `#чек-лист` embed:
   - заголовок/шапка - исходный канал (например, `#dota-2`);
   - автор - упоминание отправителя;
   - **Содержание** - текст сообщения;
   - **Ссылка на пост** - ссылка на оригинальное сообщение (переход в исходный канал).
4. **Никаких действий над оригинальным сообщением не производится** - не удаляется, не редактируется, автор не уведомляется. Это чисто информационная пересылка для модератора.
5. Пересылается **только текст** сообщения - если в тексте есть ссылка, в `#чек-лист` она попадает как обычный текст, без вложений/превью (даже если по этой ссылке есть медиа). Загрузка и пересылка самих файлов - не задача этого критерия, см. "Медиа" ниже.
6. Под пересланным сообщением бот не проставляет никаких реакций.

## Медиа → `#чек-лист2`
### Что считается "медиа"
- Фото, видео, аудио - вложения (attachments) сообщения.
- GIF-файлы как вложения.
- Ссылки на GIF из встроенного GIF-пикера Discord - технически это URL в тексте сообщения (не `attachment`), но для критерия "медиа" **приравнивается** к вложению: пересылается в `#чек-лист2` по тому же алгоритму (см. "Логика пересылки" ниже), формальная разница в типе не повод игнорировать. Распознаётся по **конфигурируемому списку доменов GIF-провайдеров** (модуль moderationChat, см. [environment.md](../environment.md) "Конфигурация") - не хардкод одного домена: Discord периодически меняет встроенный GIF-сервис (например, переход с Tenor на новый провайдер), список доменов должен обновляться конфигом, без правки кода.
- В общем - все аттачменты сообщения; плюс GIF-ссылки, отправленные текстом (по списку доменов выше). Обычные (не GIF) ссылки в тексте не пересылаются и не учитываются этим критерием.

### Логика пересылки
При обнаружении - копирует и пересылает контент в `#чек-лист2`, **в таком порядке**:
1. Сначала контент: вложения пересылаются **вместе с текстом исходного сообщения**, если он был (например, автор написал комментарий и приложил картинку - текст идёт первой строкой перед вложением, как в оригинальном сообщении, чтобы был виден контекст). Если во вложениях сообщения несколько файлов - все пересылаются **одним** сообщением. Технически - не скачивание и повторная загрузка файла, а пересылка `proxy_url` вложения (см. "Долговечность пересланной копии" ниже про его долговечность и привязку к оригиналу); Discord сам разворачивает такую ссылку в превью, визуально неотличимо от нативного вложения. Это снимает вопрос лимитов на аплоад - бот никогда не работает с самими байтами файла.
2. Затем отдельным сообщением - **embed с метаданными**:
   - название канала, откуда сообщение (например, `#игровой-общий`);
   - автор сообщения (упоминание);
   - ссылка на исходное сообщение ("Ссылка на пост").

Оригинальное сообщение в исходном канале **не трогается** - не удаляется, не изменяется.

### Долговечность пересланной копии
Механизм - пересылка `proxy_url` вложения (через `media.discordapp.net`, медиа-прокси Discord), не `attachment.url`: остаётся рабочей минимум несколько лет (не сырая подписанная CDN-ссылка с коротким сроком жизни), но привязана к жизни исходного сообщения - при его удалении пересланная в `#чек-лист2` копия тоже перестаёт отображать медиафайл.

## Хранимые данные
- Список подозрительных слов/фраз (критерий "слова") - конфиг-файл модуля (не БД, не пользовательские данные, см. [environment.md](../environment.md) - "Конфигурация").
- Для критерия "медиа" отдельного персистентного хранилища не требуется - пересылка "на лету", источник истины - сами сообщения в `#чек-лист2`.
