# Ban / Kick — базовая модерация (п.10 из base.md)

## Назначение
Стандартные модераторские наказания: бан (постоянное исключение с сервера, временный бан не поддерживается) и кик (разовое выгнание — пользователь не попадает в бан-лист, повторный вход не запрещён).

## Команды
| Команда | Синтаксис | Права |
|---|---|---|
| `/kick` / `!kick` | `<user_id> <reason>` | Модератор; причина, судя по примеру, обязательна |
| `/ban` / `!ban` | `<user_id> <reason>` | Модератор; причина обязательна |
| `/unban` / `!unban` | `<user_id> <reason>` | Модератор; причина обязательна |

Все команды доступны и как slash-, и как префиксные (`!`), аналогично [mute.md](mute.md). Подчиняются общей проверке иерархии ролей — см. [base.md](../base.md) ("нельзя наказать роль выше/равную своей").

Примеры:
```
!ban 1094877821857435680 3.2, твинк каскада
!unban 618135355169964062 есть смс (100 шт)
```

## Формат ответа бота
Отправляется embed туда же, где вызвана команда: `/kick` — в **`#бот-команды`** (вместе с `mute`/`unmute`); `/ban`/`/unban` — в отдельный канал **`#баны`**. Оба канала входят в список command-permission-ограниченных каналов вызова, боту не нужно знать их ID отдельно (см. [base.md](../base.md) "Каналы, завязанные на бота").
- полоса слева — **зелёная**;
- author эмбеда = ник + аватар модератора, вызвавшего команду (как в [mute.md](mute.md));
- блок **Причина**: текст причины.

Текст по командам (подтверждено):
| Команда | Текст в embed |
|---|---|
| `/kick` | `@упоминание кикнут с сервера` |
| `/ban` | `@упоминание забанен. Помянем.` |
| `/unban` | `@упоминание разбанен. Возрадуемся!` |

## DM-уведомления
Нет. В отличие от [mute.md](mute.md), ни `/ban`, ни `/kick`, ни `/unban` не отправляют пользователю личное сообщение.

## Логирование
Бот пишет embed в канал вызова (`#бот-команды` для кика, `#баны` для бана/разбана) только тогда, когда действие выполнено через его собственную команду из чата.

Системные оповещения о бане через нативное контекстное меню Discord (в обход бота) или о разбане через встроенный список забаненных — это отдельный вебхук, не связанный с ботом Коннор (см. [eventWatcher.md](eventWatcher.md)).

## Хранимые данные
- Отдельного хранилища не требуется — источник истины для бана/кика — сам факт бана/кика в Discord (Discord ban list для `/ban`).
- Удаление истории сообщений пользователя при бане ботом не поддерживается (нет аналога `delete_message_days`) — при необходимости выполняется отдельно, стандартным функционалом Discord.

## Обработка ошибок (точные тексты)
| Ситуация | Ответ бота |
|---|---|
| `/unban` на пользователе, которого нет в списке банов | `Не нашел пользователя <@упоминание> в списке банов` |
| Невалидный `user_id`/упоминание при `/ban` (в т.ч. когда цель уже отсутствует на сервере) | `Укажите пользователя или id. Также возможно пользователь уже отсутствует на сервере` |
| Цель — роль выше/равна инициатору, или цель — бот, при `/ban` | `Вы не можете банить старших или эквивалентных по роли или ботов` |
| Цель — роль выше/равна инициатору, или цель — бот, при `/kick` | `Вы не можете кикать старших или эквивалентных по роли или ботов` |
