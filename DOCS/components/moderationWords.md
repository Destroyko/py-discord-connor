# ModerationWords — слежение за текстом (часть п.4 из base.md)

## Назначение
Пассивный мониторинг всех текстовых сообщений на сервере на предмет подозрительных слов/фраз, с пересылкой в отдельный модераторский чат для ручной оценки — без автоматических действий над самим сообщением (слово не всегда является нарушением, зависит от контекста, поэтому решение остаётся за модератором).

Связано с [mute.md](mute.md): причина наказания "обход банворда" в примере мьюта — отдельная, более строгая проверка (обход/маскировка запрещённого слова), которая, в отличие от этого компонента, приводит к прямому наказанию модератором. Это **два независимых списка**: список подозрительных слов этого компонента (пересылка на ручную оценку) и список банвордов (прямое основание для ручного мьюта) друг с другом не связаны и не пересекаются по реализации.

## Канал
**`#чек-лист`** — сюда бот пересылает все сообщения, сработавшие по списку подозрительных слов.

## Логика работы
1. Бот проверяет каждое **новое** отправленное сообщение от **пользователя** (сообщения от других ботов пропускаются целиком, не проверяются вообще; не отредактированные — `message edit` не отслеживается) по внутреннему списку подозрительных слов/фраз — простой plain-список слов, без паттернов/регулярок (источник списка — конфиг-файл модуля, см. [base.md](../base.md) — "Конфигурация"). Список меняется только ручной правкой конфига (с рестартом бота) — отдельной команды для редактирования на лету нет.
2. Проверка применяется ко всем каналам сервера, **кроме** каналов внутри модераторской категории "роддом" (например, `#бот-команды`, `#антиработяги` и т.п. — категория без тредов/форумов внутри). Реализуется через ID самой категории (`.env`), а не перечисление отдельных каналов — на каждом сообщении сравнивается `channel.category_id` с этим ID; так исключение автоматически покрывает любой канал, который позже добавят в категорию или уберут из неё.
   - **Замечание к реализации**: сервер активно использует треды/ветки (см. [base.md](../base.md) — масштаб "80+ каналов/веток/форумов"). У объекта треда в большинстве Discord-библиотек нет прямого `category_id` — у него есть родительский канал (`thread.parent`), и уже у родителя есть `category_id`. Проверка исключения обязана резолвить тред → родительский канал → `category_id` родителя, а не пытаться читать `category_id` напрямую с объекта треда (упадёт/даст неверный результат).
3. При срабатывании — пересылает в `#чек-лист` embed:
   - заголовок/шапка — исходный канал (например, `#dota-2`);
   - автор — упоминание отправителя;
   - **Содержание** — текст сообщения;
   - **Ссылка на пост** — ссылка на оригинальное сообщение (переход в исходный канал).
4. **Никаких действий над оригинальным сообщением не производится** — не удаляется, не редактируется, автор не уведомляется. Это чисто информационная пересылка для модератора.
5. Пересылается **только текст** сообщения — если в тексте есть ссылка, в `#чек-лист` она попадает как обычный текст, без вложений/превью (даже если по этой ссылке есть медиа). Загрузка и пересылка самих файлов — не задача этого компонента, см. [moderationMedia.md](moderationMedia.md).
6. **Пересечение с moderationMedia подтверждено**: если сообщение одновременно содержит подозрительное слово И медиавложение — оно попадает **в оба** чек-листа независимо, каждый механизм срабатывает по своему критерию сам по себе.
7. Под пересланным сообщением есть несколько цветных реакций — **декоративные/нефункциональные**, в аналоге воспроизводить не нужно (подтверждено автором).

## Хранимые данные
- Список подозрительных слов/фраз — конфиг-файл модуля (не БД, не пользовательские данные, см. [base.md](../base.md) — "Конфигурация").
