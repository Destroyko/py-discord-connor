# Anti-Bot - экстренная защита от рейда ботов

## Назначение
Ручной переключатель экстренного антирейд-режима на случай массового рейда бот-аккаунтов: пока включён, сервер закрыт для новых участников. Отдельный, не связанный с [anti.md](anti.md) (статус "анти-работяга") компонент - общей логики или пересечений между ними нет.

## Команда
`/anti-bot active:<true|false>` - единственный аргумент `active` (булево), явно включает или выключает режим. Только slash, без префиксного `!`-варианта (в отличие от большинства других команд бота, которые доступны и как `/`, и как `!`, см. [base.md](../base.md) "Команды") - исключение сделано намеренно.

Кто вправе вызывать команду настраивается через штатные Discord Command Permissions (Integrations → Command Permissions, см. [rules.md](../rules.md) "Роли и права") - так же, как и у всех остальных slash-команд бота, без отдельной проверки роли в коде. Так как у команды нет префиксного `!`-варианта, реплицировать ограничение вручную для префиксного пути не требуется.

## Логика работы
1. Модератор вызывает `/anti-bot active:true`. Бот включает **временную паузу инвайт-ссылок сервера** через нативную функцию Discord **Guild Incident Actions** (в интерфейсе - Safety Setup → "Pause invites"): управляется полем `invites_disabled_until` в объекте гильдии - ISO8601-таймстемп, не булев переключатель, максимум 24 часа вперёд за один вызов; требует право **Manage Server** (см. [rules.md](../rules.md) "Роли и права"). В `discord.py` - `guild.edit(invites_disabled_until=<datetime>)`; булева форма `invites_disabled=True/False` в текущих версиях библиотеки не работает (403 либо не делает ничего) и не используется.
2. Это **временная приостановка** (не деактивация): существующие инвайт-ссылки не удаляются и не пересоздаются, просто перестают пускать новых людей, пока пауза активна.
3. **Автовыключение**: если модератор не выключил режим раньше - пауза сама снимается по истечении 24 часов (естественный потолок самого API, отдельная логика продления не нужна).
4. Модератор может выключить режим раньше явным вызовом `/anti-bot active:false` - бот сбрасывает `invites_disabled_until` тем же вызовом `guild.edit`, чтобы инвайты заработали немедленно, не дожидаясь истечения 24-часового окна.
5. Пауза не ретроактивна - она не выгоняет тех, кто уже внутри сервера на момент включения, только не пускает новых. Разбор уже вошедших аккаунтов (кикнуть/забанить/оставить) - **полностью ручное действие модератора через штатный интерфейс Discord**, без участия бота: ни отдельной команды, ни автоматизации под это нет. Автобан входящих как механика не используется вообще - слишком радикальная мера при отсутствии надёжного критерия "это бот".
6. Родственное, но отдельное поле того же API - `dms_disabled_until` (пауза входящих ЛС на сервере) - в этот компонент не входит.

## Уведомления
При переключении режима бот пишет в `#бот-команды`:
- при `/anti-bot active:true`: `@here AntiBot включён! все пригласительные ссылки на сервер временно деактивированны!`
- при явном `/anti-bot active:false`: `@here AntiBot выключён. Спасибо что воспользовались нашими услугами`

При автоматическом отключении по истечении 24 часов (см. "Логика работы" п.3) уведомление **не отправляется** - по аналогии с истечением таймаута в [mute.md](mute.md): это чисто серверный таймер Discord API, бот не получает событие в момент истечения и никак о нём не узнаёт, пока не проверит сам. Сообщение о выключении шлётся только на явный вызов `/anti-bot active:false`.

## Хранимые данные
Не требуется - состояние режима полностью хранится в самом Discord (`invites_disabled_until` в объекте гильдии), боту не нужно дублировать его у себя.
