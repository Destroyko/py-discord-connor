МИГРАЦИЯ АНТИ-СПИСКА СО СТАРОГО БОТА  (одноразово; после использования удалить connor/tools/)
==========================================================================================

ЧТО ДЕЛАЕТ
  Читает историю канала по REST (без gateway, бот ничего не отвечает), разбирает эмбеды
  старого бота «Добавление» / «Удаление» и пишет файлы для заливки в БД Connor.

ПЕРЕД ЗАПУСКОМ
  - В .env Connor заполнены BOT_TOKEN и остальные обязательные поля (конфиг валидируется).
  - У бота в канале с историей есть View Channel + Read Message History.
  - В Developer Portal включён Message Content intent (иначе чужие сообщения приходят пустыми).
  - Канал по умолчанию — #антиработяги (CH_ANTIRABOTYAGI из .env).

КОМАНДА (из корня репозитория)
  python -m connor import-anti --old-bot-id <ID_СТАРОГО_БОТА> [ключи]

КЛЮЧИ
  --old-bot-id ID     (обязателен) user id старого бота; по нему отбираются эмбеды
  --channel-id ID     канал с историей; по умолчанию #антиработяги из .env
  --after MSG_ID      начать после этого message_id (пробный прогон)
  --before MSG_ID     остановиться перед этим message_id (пробный прогон)
  --out-dir DIR       куда писать файлы; по умолчанию ./import_anti_out
  --delay СЕК         пауза между страницами по 100 сообщений; по умолчанию 1.5
  --resume            продолжить с сохранённого курсора (после обрыва, а также докачать
                      только НОВЫЕ сообщения после завершённого прогона)
  --fresh             начать заново, стерев состояние прошлого прогона
  --reset             первой командой в anti_list.sql поставить DELETE FROM anti_list;
                      (только пока Connor ещё не запущен!)

  Если в --out-dir уже лежит состояние прошлого прогона, а --resume/--fresh не указан,
  скрипт откажется запускаться и ничего не тронет.

ПОРЯДОК РАБОТЫ
  1. Пробный прогон на узком диапазоне (взять два message_id из канала):
       python -m connor import-anti --old-bot-id 123 --after 1000000000000000000 --before 1000000000000100000
     Проверить import_anti_out/events_log.csv и warnings.log глазами.
  2. Полный прогон:
       python -m connor import-anti --old-bot-id 123 --fresh
  3. Если прервался (Ctrl+C, сеть, падение) — продолжить:
       python -m connor import-anti --old-bot-id 123 --resume
  4. Непосредственно перед заменой бота — докачать то, что добавили/удалили после
     основного прогона, и пересобрать файлы:
       python -m connor import-anti --old-bot-id 123 --resume --reset
  5. Проверить warnings.log: последняя строка «ИТОГ» с числами; сверить число «итоговых add».

ФАЙЛЫ НА ВЫХОДЕ (в --out-dir)
  anti_list.sql     основной артефакт: INSERT OR IGNORE INTO anti_list ... (в транзакции)
  anti_list.json    то же для ручной проверки
  events_log.csv    все распарсенные события (message_id, ts, iso_utc, action, user_id,
                    added_by, footer_raw)
  warnings.log      что не распарсилось (нет id, не найден автор !add -> added_by=0 и т.п.)
                    + итоговые числа в последней строке
  .state.json, .events.jsonl   служебные: курсор и накопленные события для --resume

ЗАЛИВКА В БД CONNOR (бот остановлен, миграции применены, таблица anti_list существует)
  sqlite3 /path/to/connor.sqlite3 < import_anti_out/anti_list.sql
  sqlite3 /path/to/connor.sqlite3 "SELECT count(*) FROM anti_list;"
  Число должно совпасть с «итоговых add» из warnings.log (при пустой таблице или --reset).

ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
  - «нет доступа к каналу» (403/404): нет прав на канал или неверный --channel-id. Скрипт
    останавливается сразу, повторных запросов не шлёт.
  - В warnings.log «эмбеды есть, но ни один не распознан»: скорее всего выключен
    Message Content intent.
  - Много «не найден автор !add»: команды удалены из канала или написаны не с «!add id».
    Для статуса это не важно (added_by=0 нигде не используется).
  - Нет сети / 5xx: скрипт сам ждёт и повторяет ту же страницу (паузы до 5 мин). Остановить
    можно Ctrl+C, потом --resume.
